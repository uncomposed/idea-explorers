# Shared reader human-factors review — 22 September 2026

## Task and boundaries

A newcomer must identify an idea, understand its main mechanism and vocabulary,
inspect the relevant model statement, and reach a working interpretation. A model
author must still be able to audit the exact source. The scarce resource is the
reader's attention; the YAML remains optimized for faithful representation.

Separate layers: editorial explanation; definitions and typed propositions;
relationships; proposed checks; source provenance; external experiences. A source
contribution is not empirical validation, and a proposed test is not a result.

## Acceptance checks

- All seven registry entries have pinned model bytes, a semantic adapter, a reading
  guide, and a real experience destination. Inventory tests catch omitted ideas.
- Names replace bare model codes in navigation, reference links, cards, and checks.
  Source identifiers appear only after the full proposition, explicitly labeled.
  The prior K5/K7 failure and the leaked boundary instruction have regression tests.
- The experience action immediately follows the title. At 320 × 568 CSS pixels,
  its bottom edge was between 249 and 318 pixels for every idea, without scrolling.
  All seven overview pages had no horizontal document overflow.
- Each idea's first explanation was opened, followed through a named reference to
  an exact Git source line, then closed with Escape. Focus returned to the opener
  in all seven cases. A mobile native dialog also contained reverse-tab navigation.
- Semantic headings, named navigation, labeled selects/search, skip link, visible
  focus, current-page indication, browser Back, and shareable selection URLs are
  retained. Mobile navigation is a visible two-column list, not an offscreen strip.
- Primary actions are at least 48px high; selectors, dialog close controls, source
  references and disclosures have 44px targets. Ordinary inline links retain their
  text context. Input/control boundaries use a darker border than decorative rules.
- Desktop directory checked at 1280 × 900: seven cards, consistent actions, no
  document overflow. Source panels preserve every source section; automated checks
  verify source lines, typed relationships, guide references, and exact model bytes.

These checks operationalize WCAG 2.2 guidance on
[reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html),
[target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html),
and [labels](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html),
alongside recognition over recall, progressive disclosure, and consistent actions.

## Explicit limitations and exceptions

- This is a scoped review, not certification against every human-factors standard
  or every WCAG criterion. Screen-reader sessions, operating-system text scaling,
  every browser, and user comprehension studies have not been completed.
- The source view preserves original code labels and technical language for audit.
  Full propositions can contain technical notation; the overview supplies a
  vocabulary. Editorial explanations are visibly identified as reading aids.
- The CTA guarantee was checked at 320 × 568 and larger typical viewports; unusually
  short windows or extreme magnification can require scrolling. The compact mobile
  header omits the version/status badge; exact version remains in the footer/source.
- Cislunar's registered experience is a downloadable project requiring local setup.
  Spoken Margins opens an iOS TestFlight beta, subject to Apple's availability.
  AI Pacing opens a specialized policy explorer. These are labeled accurately;
  external applications are not included in this viewer's accessibility review.
- The full source can require horizontal scrolling within its code container.
  Tables/code that depend on two-dimensional layout are distinct from page reflow.
- No audio narration, video, timed interaction, or drag-only action was introduced.
  The page does not manufacture empirical evidence where the model has none.

## Audit and stopping rule

Compare this shared renderer with maintaining seven independent UIs: shared
navigation and accessibility fixes converge, while adapters preserve different
model semantics. Reject a release if a registered idea is omitted, an ID cannot
resolve, model bytes drift, an editorial reference lacks a source, or the mobile
experience action falls below the tested viewport. Build, semantic tests, manifest
verification and browser acceptance checks must pass before publishing. Preserve
old assets and releases so improving the current interface does not rewrite history.
